## 음식에서 실험 결과까지

음식명과 섭취량을 입력하면 선택한 식품 기록의 함량으로 성분 섭취량을 계산합니다.
관련 사람 연구를 찾은 뒤 시험에서 사용한 음식·제품·성분과 용량·기간·조직·대조 조건을 확인합니다.
그 실험의 유전자 발현·DNA 메틸화·경로 결과를 분석 버전과 출처까지 따라 조회합니다.

같은 연구에서 보고한 혈압·지질·BMI·허리둘레는 별도 건강지표 기록으로 연결합니다.
분자 결과와 임상지표를 함께 조회하는 기능입니다. 유전자 변화가 임상 변화를 일으켰다는
매개·인과 관계는 근거가 확인된 경우에만 별도로 다룰 수 있습니다.

기전과 계산 예측은 사람 중재 결과와 구분합니다. 자동 문헌 추출은 검토 후보로 관리하며,
공개·수록 판정 전에는 확정 근거로 제공하지 않습니다. 연결이 없으면 자료 부족으로 남깁니다.

## 여섯 종류의 자료

| 구성 | 저장하는 내용 | 연결 기준 |
|---|---|---|
| 음식 | 이름·별칭·조리상태·원본 식품 코드 | 식품 ID |
| 성분과 함량 | 영양성분·화합물, 함량·단위·기준·결측·출처 | 식품 ID와 성분 ID |
| 사람 중재 | 연구·노출·군·용량·기간·조직·대비 | 연구·노출·군·대비 ID |
| 오믹스 결과 | 유전자·probe·영역 검정·경로의 효과량과 통계 | 아래 다섯 부분 분석 키 |
| 건강지표·외부 맥락 | 같은 연구의 임상 요약, 별도의 조절 주석·기전·예측 | 연구 ID 또는 출처가 있는 개별 관계 |
| 출처·검수·재현 | 원본 URL·버전·해시·이용조건·판정·분석 설정 | 대상 기록과 파일의 ID·해시 |

오믹스 결과의 분석 키는 `series + feature_type + feature_id + contrast + analysis_version`입니다.
같은 유전자라도 연구·대비·분석 버전이 다르면 별도 결과로 유지합니다.
CpG의 근접 유전자 주석, eQTM, 시험한 조절 관계와 계산 예측도 별개입니다.
고정 1 kb 영역 검정은 발견·검증된 DMR 수로 표시하지 않습니다.

## 실제 저장 방식

SQLite의 `node`, `measurement`, `edge`는 항목·조성·유형별 관계를 저장합니다.
`science_record`는 연구·노출·군·대비·분석·주장·임상 기록을 보관합니다.
대형 정량 결과는 효과 테이블과 CSV/Parquet로 제공하고 분석 키로 연결합니다.
색인은 원래 결과를 가리키며 조회를 빠르게 합니다.

원본, 정제 자료, 분석 결과와 운영판을 분리합니다. `manifest.json`과 파일 해시는
해당 자료 버전의 내용과 입력을 확인하는 기준입니다. 데이터가 바뀌면 차이 검사와
검수 단계를 거쳐 새 버전을 만들며, 이전 자료를 보존합니다.

## 요구르트 150 g의 예

1. 요구르트의 종류와 원본 식품 기록을 선택합니다.
2. 함량 기준이 확인된 성분을 150 g에 맞춰 계산합니다. 미측정이나 기준 미확인은 구분합니다.
3. 800 g 시험이 연결되면 입력량과 시험량의 차이, 제품 동일성, 측정 시점을 표시합니다.
4. 연구의 원래 비교 조건에서 발현·경로·임상 결과를 조회합니다. 효과량을 150/800 비율로 환산하지 않습니다.

이 구조는 모든 음식에서 유전자·건강 결과까지의 연결이 완성됐다는 뜻이 아닙니다.
현재 수록 범위와 검수 대기는 [검토 안내](REVIEWER_GUIDE.ko.md),
집계 단위와 해시는 [기준 수치 파일](reference-data-summary.json)에서 확인할 수 있습니다.
