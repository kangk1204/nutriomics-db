# NutriOmics Explorer 화면 개선 및 검증 — 2026-10-09

디자인 구현과 운영 반영을 완료했다. 대량 식품 근거 조회의 현재 서버 성능은 합격으로 판정하지 않았다. 이 문서는 UI 변경에 대한 기록이며, 과학적 정확성 평가나 개인 건강 예측 검증 보고서가 아니다.

## 반영한 변경

- Sites의 기존 프로젝트 개선 흐름을 적용했다. 승인된 연구실 서버에서 제공하며 클라우드 공개·로그인·새 기관 설정은 추가하지 않았다.
- 검색 표, 근거 비교, 발현·DNAm, 조절 위치, 연결망, 상세 패널에 같은 서체 크기와 여백·선택 상태를 적용했다. 본문 16px, 주요 조작·표 14px, 보조 정보 12px를 기준으로 했다.
- 음식·영양성분·화합물·유전자·CpG·질환·건강지표의 원래 유형을 유지했다. 연구와 대상자, assay, 관계 수를 서로 바꾸어 표시하지 않는다.
- 동일 노출, 동일 분석 성분, 관련 식품, 공통 성분을 공유한 복합 중재를 표와 상세에서 구분한다. 원래 대응 방법·설명은 보존한다.
- 사람 연구 수는 연구 ID, 대비 수는 연구·series·대비 ID·분석 버전의 조합으로 중복 제거한다. 동일 대비가 활성군과 대조군 노출에 반복되어도 두 개의 독립 대비로 집계하지 않는다. 실제 보존 snapshot에서 노출–대비 79행은 고유 대비 56개, 연구 6개다. 대상자 수를 합산하지 않았다.
- 긴 근거 ID와 원문 집계 범위는 펼쳐서 확인한다. 원본 수치·단위·결측과 출처를 유지한다.
- 조회 중, 조회 실패, 미수록, 미보고, 실제 0을 구분한다. 조회 실패를 근거 부재로 처리하지 않는다. 검수 미확인을 승인이나 대기로 임의 변환하지 않는다.
- 연결망에 최소 그리기 영역을 확보하고 확대 작업 공간을 제공한다. 연결망 탭에서 비교 조건 입력을 숨긴다. 조절 위치는 원래 기록을 유지하면서 약 20개씩 축 범위를 확대할 수 있다.
- 작은 화면에서는 검색·작업·상세 중 하나의 패널을 표시한다. 입력과 버튼 이름, 키보드 이동, 읽기용 표, 로딩 상태를 제공한다.
- 독립 HTML에 최신 JS와 CSS를 모두 포함한다. 서버 통신은 CSP `connect-src 'none'`으로 차단한다. 이용조건에 따라 제외한 상세는 기존 정책을 유지한다.

## 남은 제한과 다음 검증

서버 복구 직후 staging과 기존 운영 API 양쪽에서 대량 식품 graph/match 조회가 지연되었다. staging 요청은 30초 제한시간에, 운영 graph 확인은 10초 제한시간에 걸렸다. 서버 스레드의 디스크 페이지 대기와 Linux IO pressure 상승을 직접 확인했다. 원인을 UI 변경으로 단정하지 않았으며, 기존 backend와 DB는 수정하지 않았다.

따라서 이번 작업의 warm p95 ≤1초 기준은 미검증이다. 성능 개선의 다음 단계는 동일 요청의 SQL별 시간·읽기량을 기록하고, 고정 release별 식품–중재 대응·효과 총수의 사전 계산 및 조회 캐시를 평가하는 것이다. 최종 판단은 디스크 대기가 해소된 반복 측정과 결과·출처 완전성 비교 후에 내린다. 임의로 응답 제한시간을 늘리거나 자료를 줄여 통과한 것으로 처리하지 않았다.

Vite의 기존 대형 JS bundle 경고도 남는다. 필요하면 그래프·오믹스·좌표 모듈을 분할하고 실제 첫 표시 시간을 측정한다. 이번 변경을 근거로 검증된 SOTA 성능이나 임상 효과를 주장하지 않는다.
